# Precious Promises Content & Growth Dashboard

## Project identity

- **Dave is the Founder & Creator of Precious Promises.** He is the approver of
  record for anything this product would publish.
- **This repository is separate from the Precious Promises Bible app.** Do not
  import from it, copy its code, or assume shared infrastructure.
- **This repository is separate from Genesis O.S and Genesis Dominion.** Do not
  access those systems, and do not reference them in code, configuration or
  documentation.

## How to work here

- **Work one controlled stage at a time.** A stage is delivered in numbered
  blocks. Finish the current block, validate it, and stop.
- **Do not begin a later block or stage without explicit approval.** Finishing
  early is not permission to continue.
- **Run validation after every block:** `pnpm format:check`, `pnpm lint`,
  `pnpm typecheck`, `pnpm test`, `pnpm build`.
- **Preserve approved architecture and working features.** Refactors that
  discard agreed structure or break shipped behaviour need approval first.

## Integration work

- **Research official API requirements before integration work.** Read the
  current vendor documentation at the time of implementation.
- **Do not invent social-platform API behaviour.** Endpoints, scopes, rate
  limits, media constraints and review requirements change often. If a detail
  cannot be verified against official documentation, stop and ask rather than
  guessing.
- **Do not fake successful publishing.** A publish path that has not genuinely
  reached the platform must report failure. Never stub a success response,
  and never mark a post as published because the code path completed.

## Content and approval

- **Never publish unapproved content.** Human approval is mandatory before
  anything leaves this system.
- **Editing approved content invalidates approval.** Any change to media,
  Scripture, captions, metadata or thumbnails returns the item to an
  unapproved state and requires re-approval.

## Scripture handling

- **Never invent a Bible verse or Scripture reference.** Do not generate,
  paraphrase or reconstruct verse text or citations from memory.
- **Never silently alter verified Scripture.** Verse text and references are
  treated as verified data; changes must be explicit, attributed and reviewable.
- **Keep Scripture separate from declarations, prayers and commentary.** These
  are distinct content types and must remain distinguishable in data, in the
  interface and in anything published.

## Secrets

- **Keep all secrets server-side.** Only `NEXT_PUBLIC_*` values may reach the
  browser. Server-only configuration is read through `src/lib/env/server.ts`
  and must never be re-exported from `src/lib/env/public.ts`.
- **Do not commit credentials.** `.env.example` holds placeholder keys with no
  values. Real values belong in untracked `.env` files and in the deployment
  platform's secret storage.
- Never log secret values, and never include them in error messages — including
  validation errors.
